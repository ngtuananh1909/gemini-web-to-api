# Image generation and image inputs

The gateway extracts and downloads images generated by Gemini Web, then exposes
them through the OpenAI-compatible API. Requests require the configured gateway
API key when authentication is enabled (the default). If `API_KEY` is empty,
the gateway persists a local key under `GATEWAY_DATA_DIR`.

## Supported workflows

- Text-to-image through the OpenAI-compatible `POST /openai/v1/images/generations` endpoint.
- Image input through OpenAI-compatible chat messages.
- Multiple reference images in a single chat request.
- Generated-image output as `b64_json`.
- Generated-image links in chat responses.

> Gemini Web is an undocumented interface. Available image models and internal response layouts may change without notice.

## Text-to-image

Choose an image-capable model returned by `GET /openai/v1/models`. Model IDs
depend on the signed-in Gemini Web account and can change after a refresh:

```bash
export API_KEY='replace-with-a-long-random-value'
export GEMINI_IMAGE_MODEL="$(curl -s http://127.0.0.1:4981/openai/v1/models \
  -H "Authorization: Bearer $API_KEY" | jq -r '.data[0].id')"
printf 'Using model: %s\n' "$GEMINI_IMAGE_MODEL"
```

The list comes from the signed-in account's Gemini Web model registry. Use the
returned ID or set `GEMINI_IMAGE_MODEL` explicitly after checking that the
account supports image generation. Names from old Gemini API releases are not
mapped to a different web model.

### cURL

```bash
curl http://127.0.0.1:4981/openai/v1/images/generations \
  -H "Authorization: Bearer $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "'"$GEMINI_IMAGE_MODEL"'",
    "prompt": "Generate an image of a red apple on a white plate.",
    "size": "1024x1024",
    "n": 1,
    "response_format": "b64_json"
  }'
```

The response follows the OpenAI image-generation shape:

```json
{
  "created": 1730000000,
  "data": [
    {
      "b64_json": "iVBORw0KGgo...",
      "revised_prompt": "Generate an image of a red apple on a white plate."
    }
  ]
}
```

Save the returned image with Python:

```python
import base64
import os
import requests

api_key = os.environ["API_KEY"]
model = os.environ["GEMINI_IMAGE_MODEL"]
response = requests.post(
    "http://127.0.0.1:4981/openai/v1/images/generations",
    json={
        "model": model,
        "prompt": "Generate an image of a red apple on a white plate.",
        "size": "1024x1024",
        "n": 1,
        "response_format": "b64_json",
    },
    headers={"Authorization": f"Bearer {api_key}"},
    timeout=360,
)
response.raise_for_status()

image = base64.b64decode(response.json()["data"][0]["b64_json"])
with open("generated.png", "wb") as file:
    file.write(image)
```

### OpenAI Python SDK

```python
import base64
import os
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:4981/openai/v1",
    api_key=os.environ["API_KEY"],
)

response = client.images.generate(
    model=os.environ["GEMINI_IMAGE_MODEL"],
    prompt="Generate an image of a red apple on a white plate.",
    size="1024x1024",
    response_format="b64_json",
)

with open("generated.png", "wb") as file:
    file.write(base64.b64decode(response.data[0].b64_json))
```

## Image input and multiple references

Image input uses the OpenAI multimodal chat format. The current OpenAI-compatible endpoint accepts base64 `data:` URLs. Remote HTTP(S) image URLs are not downloaded by the bridge.

```python
import base64
import os
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:4981/openai/v1",
    api_key=os.environ["API_KEY"],
)


def data_url(path: str, mime_type: str) -> str:
    with open(path, "rb") as file:
        encoded = base64.b64encode(file.read()).decode()
    return f"data:{mime_type};base64,{encoded}"

response = client.chat.completions.create(
    model=os.environ["GEMINI_IMAGE_MODEL"],
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "text",
                    "text": (
                        "Generate a new square image using both references. "
                        "Keep the subject from the first image and use the "
                        "second image as the background. Return the image."
                    ),
                },
                {
                    "type": "image_url",
                    "image_url": {"url": data_url("subject.jpg", "image/jpeg")},
                },
                {
                    "type": "image_url",
                    "image_url": {"url": data_url("background.png", "image/png")},
                },
            ],
        }
    ],
)

print(response.choices[0].message.content)
```

Chat image output is currently returned as Markdown containing the generated-image URL. These Google-hosted URLs may require the same authenticated Gemini session to download. For a directly portable base64 result, prefer `/images/generations`.

## How generated images are handled

Gemini Web does not place every generated image in ordinary response text. Generated-image metadata is stored in a dedicated candidate media slot. The provider:

1. Parses the structured media slot.
2. Extracts URL, MIME type and dimensions.
3. Downloads the image with the active Gemini Web cookies.
4. Returns portable base64 bytes through `b64_json`.

The authenticated download is deliberately performed inside the provider. Sending a raw Google-hosted URL to an unauthenticated client commonly results in HTTP `403`.

## Tested behavior

The implementation has been verified with:

- a text-to-image request returning a valid PNG;
- a prompt requiring exactly three separate objects around Earth;
- a chat request containing two input images;
- generated PNG responses larger than 1 MB;
- unit tests for structured image extraction and Google image URL transforms.

## Limitations

- Selectable web models are discovered per account and can change; image generation also depends on account access and the prompt.
- `n > 1` may require multiple upstream generations.
- Some prompts may return text without an image.
- Generated-image URLs in chat responses are session-bound and may expire.
- Video generation and Web TTS are not part of this image implementation.
- Cookie rotation errors are not always proof that live Gemini requests have stopped working; verify with a real request.

## Security

`GEMINI_COOKIES` grants access to the Google session used by the bridge.

- Never commit cookies or a populated `.env` file.
- Keep `API_AUTH_ENABLED=true` and send `Authorization: Bearer $API_KEY` or `x-api-key` on API calls.
- Keep the dashboard local. Set `DASHBOARD_ENABLED=false` when only the API should run.
- Bind the service to localhost unless a reverse proxy and firewall protect a remote deployment.
- Do not publish logs, HAR files or browser profiles from authenticated sessions.
- Use restrictive file permissions for cookie caches.
- Revoke the Google session if credentials are accidentally exposed.

A safer local Docker port binding is:

```bash
docker run -d \
  -p 127.0.0.1:4981:4981 \
  --env-file .env \
  --name gemini-web-to-api \
  gemini-web-to-api:local
```

The example intentionally contains no real hosts, account names, cookie values or access tokens.
